# DataBard — Anna App

**How healthy is your sheet?** Bundle-only Anna App (no executas): paste a
CSV/TSV → deterministic health score (`community-health.js`, generated —
never edited) → one `llm.complete` writes a reading → a deterministic audit
decides what ships → saved result. Rows never leave the window.

## Layout

```
bundle/
  index.html            static shell — all screens render before the host connects
  clock.js              ?clock=<ISO> capture hook — pins Date before load, no-op otherwise
  app.css               DataBard surface contract (vars in :root, no emoji, system fonts)
  app.js                screens, host wiring, entry payload {tone?} — DOM only
  community-health.js   GENERATED by ../scripts/build-anna-scorer.mjs — do not edit
  reading.js            reportPayload (samples stripped), prompt, parser, auditReading, readReport
  repair.js             in-window cleaned CSV + change log (rows never leave)
  compare.js            since-last-check snapshot + deterministic diff (aggregates only)
  recovery.js           databard/active-task checkpoint + readings/<ts>, readings/last
  session.js            unwrap/storage helpers, withTimeout
test/
  scorer.mjs            drift check (re-transpile and compare) + SAMPLES sanity
  reading.mjs           payload hygiene, parser, audit cases, redraft paths
  repair.mjs            clean/dedupe/change-log cases, no-rows guarantee
  compare.mjs           snapshot hygiene + diff cases (same/different sheet, directions)
  recovery.mjs          checkpoint validate/corrupt/resume, no-rows guarantee
  fake-anna.js          in-memory fake host
  smoke.mjs             happy path + unnarrated path + no-member-data-on-wire
```

## Flow

1. **Input** — paste box, .csv/.tsv file (≤5 MB, ≤50,000 rows), three
   samples, tone toggle (straight / roast). Entry payload `{tone?}` only.
2. **Score** — `analyzeCommunityData`, then checkpoint `{stage:"reading",
   tone, payload}` seals the report payload (never rows).
3. **Clean** — `planRepair` trims, drops empty rows, normalises emails and
   dedupes by email (or whole row). The cleaned CSV stays in the session; the
   record carries only the change log (counts and column names).
4. **Compare** — the previous saved reading's snapshot diffs against this
   one (`compare.js`): score, members, contactable, empty cells, checks that
   changed state. A different sheet yields no diff, not a meaningless one.
   The diff rides inside the model payload as `sinceLast`, so its numbers
   are auditable — and the model may narrate what moved.
5. **Reading** — one `llm.complete` (max 2 with the violations redraft);
   the contract asks for a purpose `verdict` and a `priority` ordering over
   the report's own checks — decisions the model makes and the audit binds.
   `auditReading` drops any paragraph with an invented figure, unknown
   quoted name, email or URL, a verdict that restates the label, and plan
   entries that name a check the report does not have. Unnarrated results
   save `narrated:false` and the UI shows the deterministic report with the
   honest line.
6. **Saved** — `readings/<ts>` + `readings/last`; Home shows "Last reading".

## Tests

**Tier 1 — free, every change**

```bash
cd anna
npm test                     # node --test + smoke via fake host
npm run test:browser         # agent-browser QA on the fake host — no quota
anna-app validate --strict
(cd .. && npx tsc --noEmit && npm run test:unit)   # shared scorer contract
```

Browser QA without quota: `test/fake-host-server.mjs` serves the bundle
with a scripted fake host (`/__script`, `/__fault`, `/__delay`, `/__kv`,
`/__dump`); `test/browser-qa.mjs` drives it with agent-browser under the
session name `databard-anna-qa`.

**Tier 2 — cheap, only when a prompt changes**

- UI/layout: `anna-app dev --mock-llm test/mock-llm.jsonl` (no quota).
- Prompt quality without Anna quota: `node scripts/prompt-check.mjs` —
  runs the real prompt builders and the audit against an own-key model
  (see the script header for which key/env it needs).
- `anna-app dev` logged in uses real Anna models and **consumes account
  quota** — small batches only.

**Tier 3 — Anna Cloud Agent, once per release candidate**

Fixed checklist, each step in a NEW chat (context size drives cost):

1. Developer Console → Install the build; open a fresh chat and ask for a
   data-health check on a member list.
2. Confirm the window opens via `open_app_view`, the visible reply is the
   fixed line only, and no CSV was requested in chat.
3. Paste a sheet (or use a sample), pick a purpose, Run — confirm the
   score, the purpose-specific reading and the honest line if the reading
   could not be checked.
4. Close the window mid-run, reopen it, Resume — confirm "Last reading"
   restores and no member data reached the checkpoint.

Regenerate the scorer after changing `../src/lib/community-health.ts`:
`node ../scripts/build-anna-scorer.mjs`.

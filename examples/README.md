# Examples — DataHub integration outputs

Sample artifacts produced by DataBard's DataHub integration, generated by running
the **real** analysis pipeline (`buildSchemaMeta` → `analyzeSchema` →
`generateActionItems` → `planTableWriteBack`) against a representative `db.sales`
DataHub dataset set. See `scripts/gen-examples.ts`. No live DataHub instance is
required to inspect these.

| File | What it shows |
|------|---------------|
| `schema-meta.json` | What the DataHub adapter returns (`buildSchemaMeta`) — datasets, columns, PII tags, owners, quality assertions, lineage. |
| `health-check.json` | The `databard_health_check` tool output — health score, critical tables, stale/ownerless/undocumented counts, recommended actions. |
| `write-back.json` | The `databard_write_back` tool plan — the tags + AI summary the agent writes back into the DataHub context graph. |
| `briefing.json` | Representative output of the paid `databard_briefing` (script + audio + health). Illustrative — a real briefing needs an LLM + TTS key, so this one is hand-shaped to match the documented schema. |

Regenerate the pipeline artifacts:

```bash
npx tsx scripts/gen-examples.ts
```
